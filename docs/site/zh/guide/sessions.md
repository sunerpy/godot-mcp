# 游戏与编辑器

在 `runtime` 和 `full` profile 下，服务器会启动并持有长期运行的 Godot 进程：用 `project.run.start` 启动的**游戏会话**，以及用 `editor.session.start` 启动的**编辑器会话**。会话只属于启动它的那个服务器，只能通过一个不透明的 ID 来识别（`run_` 或 `editor_` 后跟 32 位十六进制数字）。包括导出在内，同时最多运行四个会话，每个会话最晚在它的 `lifetimeSeconds` 到期时结束——默认一小时，最长四小时。

## 运行游戏

`project.run.start` 运行主场景或 `scene`，并带上服务器自己的运行时探针，通过命令行传给 Godot：项目不会为此做任何改动，不会安装自动加载，也不会改任何设置。探针通过一条只属于这个会话的回环连接连回服务器之后，调用才会答复，所以拿到答复的会话已经可以使用。

`display` 决定游戏怎样绘制：`window` 绘制到服务器启动时所在的显示环境，`headless` 完全不绘制，默认的 `auto` 在有显示环境时等同于 `window`。截取需要窗口。在 Linux 上，Xvfb 这样的虚拟 X 显示就足够了；在 macOS 上，服务器必须运行在已登录用户的会话里；在 Windows 上，必须运行在已登录会话的可见桌面上。

`project.run.status` 报告会话的状态、场景、显示方式、限定方式和按住的输入；`project.run.logs` 分页读取它捕获的输出，运行中和结束后都可以读；`project.run.stop` 松开所有按住的输入，请游戏退出，游戏不退出就结束它。

## 发送输入

`input.key.send`、`input.mouse.send`、`input.action.send` 和 `input.sequence.send` 用来按下、松开或轻按按键、鼠标按钮和输入动作，以及移动鼠标；一个序列最多 64 步，步骤之间可以等待。按住的一切都会在这些时候被松开：保持时间结束时（`holdMs`，默认 500 毫秒）、被显式松开时、按下它的序列结束或被取消时、会话停止时，以及游戏失去服务器时。每次输入调用都写进日志并带 `idempotencyId`，所以重试的调用会从日志里取回结果，而不会再按一次。

## 读取运行中的游戏

`runtime.tree.get`、`runtime.properties.get`、`runtime.signals.get` 和 `runtime.ui.get` 通过探针读取游戏，不改动游戏：带类、脚本、分组和可见性的场景树，一个节点的属性（带类型的值），一个节点的信号和连接（设置 `watch` 后还会统计之后的每次发射），以及可见控件的矩形、文本和焦点。每个答复都写明探针的场景版本号和它取自哪一帧。

`runtime.performance.get` 读取游戏的性能监视器：帧率和帧耗时、对象和节点数量、内存、渲染、物理、音频和导航数据，名字沿用你所用 Godot 版本里的叫法，比如 `TIME_FPS` 和 `OBJECT_NODE_COUNT`，并附带项目自己添加的自定义监视器。用 `monitors` 指定名字可以只读这些；这个版本没有的名字会被拒绝。

## 操控和观察游戏

`runtime.properties.set` 用带类型的值写入一个节点的属性，或者 Engine 的 `time_scale`、`physics_ticks_per_second` 和 `max_fps`。值只在不丢失任何信息时才会转换成属性的类型——1.5 永远不会写进 `int` 属性——写不成的请求什么都不改。每个属性写完都会读回，所以 setter 截断或忽略了值时，答复里会显示 `matched: false`。`runtime.properties.batch.get` 一次读取多个节点以及 Engine 的属性。

`runtime.wait` 最多等 30 秒，直到某个节点出现或消失、某个属性与给定值满足比较（`==`、`!=`、`<`、`<=`、`>`、`>=`、`contains`，或在容差内的 `approx`）、某个信号发射了指定次数，或者某个控件显示了某段文本。无论条件成立还是超时，答复都带上最后一次看到的情况。`runtime.sample` 按间隔读取属性和性能监视器，最长 10 秒，每个序列都给出最小值、最大值、平均值和最后一个值，并标出每次采样时游戏是否暂停。

`runtime.nodes.find` 按类（包括继承的类）、脚本、分组、名字模式和距离查找节点，近的排在前面。`runtime.navigation.path.get` 向节点所用的导航地图查询路径；`runtime.node.move` 把节点放到某个点，或沿那条路径走过去。移动是直接设置节点的位置，游戏自己的移动代码和碰撞不会为它运行。

`runtime.ui.press` 按路径或按显示的文本找到一个按钮，在它的中心用左键点击，并答复它的 `pressed` 信号是否发射。无界面会话的窗口只有 64×64 像素，超出这个范围的按钮需要窗口会话。

`input.recording.start` 和 `input.recording.stop` 录下游戏收到的输入，标出哪些事件是服务器发出的、哪些来自别处，并把录制结果保存为产物。`input.replay` 按原来的时间重新发送录下的事件，结束时松开它仍按住的一切。

探针一次只处理一个请求，所以较长的等待、采样、行走或回放会让这个会话的其他请求排在后面，而且同一项目里的命令也会互相等待。取消这次调用可以让它立即结束；`project.run.stop` 会先结束正在运行的请求，再停止游戏。

用 `--allow-scripts` 启动服务器后，`runtime.script.run` 会在运行中的游戏里执行 Agent 写的 GDScript。脚本能看到当前场景、自动加载和全部引擎 API，答复里给出它的 `run()` 返回了什么、打印了什么、报了哪些错以及出错的行（Godot 4.5.1 起），还有运行前后内容不同的每个项目文件。Godot 无法让脚本中途停下：服务器停止等待时——过了 `deadline_ms` 再加两秒，或者调用被取消——答复是 `uncertain`，代码仍在游戏里继续运行。停止会话才能结束它。

## 截取

`runtime.screenshot.capture` 把根视口截成一张 PNG；`runtime.recording.capture` 以最多每秒 30 帧录制最长 10 秒，生成一个动态 PNG。每一帧都对照探针报告的摘要校验，答复把截取结果作为一个产物——带媒体类型、大小和 SHA-256 的不透明 URI——客户端用 `resources/read` 读取。产物默认在 15 分钟内可读，同一个客户端打开的任何会话都能读取它：客户端即使在截取和读取之间重新连接，也仍能读取它（见 [HTTP 会话](../operate/http.md#会话)）。无界面会话不渲染画面，在其中截取会答复 `unavailable`。

## 测试游戏

`runtime.time_scale.set` 让运行中的游戏变快或变慢：它设置 `Engine.time_scale`（0 到 100；1 是正常速度，0 让游戏时间停下）并读回结果。改动只存在于运行中的游戏里，不会写进项目，一直保持到你再次修改或会话结束。

`runtime.image.compare` 在下一帧绘制后截取游戏画面，与项目里的一张 PNG 逐像素比较。答复给出两张图是否一致、有多少像素在某个颜色通道上的差异超过 `tolerance` 以及它们占整张图的比例、最大的通道差异和包住所有差异像素的矩形，截图和差异图都作为产物保存。尺寸不同的两张图判为不一致，不会缩放。它需要窗口会话。

`test.scenario.run` 在一次调用里按顺序执行最多 64 个步骤，并答复一份报告：输入、等待、写属性、按按钮、调整时间缩放、对属性或控件文本的断言、截图、图像比较，以及压力步骤——添加最多 1000 个场景实例，观察帧率和节点数量，并检查结束后每个实例都已释放。每个步骤的结果是 `passed`、`failed`（附带期望值和实际值）、`error`、`skipped` 或 `uncertain` 之一。默认在第一次失败后跳过其余步骤，把 `stopOnFailure` 设为 `false` 可以继续执行；无法判定结果的步骤会结束整个运行；`maxDurationMs` 限制总时长。只有所有步骤都通过，结论才是 `passed`；报告还会另存为一个 JSON 产物。文本断言读取的是控件的 `text` 属性，不会把屏幕内容识别成文字。

## 调试

`editor.session.start` 在项目上启动一个无界面的 Godot 编辑器，它的 GDScript 语言服务器和调试适配器监听服务器分配的回环端口；只有当这两个端口都在监听、并且确实由这个编辑器进程持有时，调用才会答复。之后 `debug.command` 通过会话的启动凭据发送一条命令：

| 服务 | 命令 |
| --- | --- |
| 语言服务器 | `diagnostics`、`symbols` |
| 调试适配器 | `breakpoints`、`launch`、`stopped`、`stack`、`scopes`、`variables`、`continue`、`pause`、`stop` |

行号从 1 开始。没有表达式求值，也没有单步跳出，因为 Godot 的调试适配器没有实现它们。`debug.session.get` 报告连接、调试运行、最近一次停下以及断点；`editor.session.stop` 结束编辑器以及它在调试器下运行的游戏。

## 崩溃之后

正常停止的服务器会先停止它的会话。下一个为同一项目启动的服务器，会在提供任何服务之前结束前一个服务器遗留的所有会话，并把每个会话记为 `reconciled`；如果无法证明它的边界已经清空，就记为 `quarantined`。它们的状态和输出仍然可以读取。全部规则见[托管会话参考](../../../operator/managed-sessions.md)。
