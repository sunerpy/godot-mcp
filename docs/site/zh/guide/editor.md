# 编辑器插件

`godot_mcp` 编辑器插件把你正在运行的 Godot 编辑器连到服务器上。有了它，MCP 客户端可以查看编辑器持有的内容，以普通、可撤销的编辑器操作修改场景、保存并关闭它们，看到编辑器窗口，读取编辑器日志，修改编辑器自己的设置，让编辑器接收磁盘上变化的文件，打开脚本，运行游戏；服务器照常执行它的日志、策略和恢复规则。它需要 `editor` 或 `full` profile；`runtime` profile 只提供运行游戏的两个工具。

## 安装插件

| 工具 | 作用 |
| --- | --- |
| `editor.addon.status` | 逐个文件比较 `addons/godot_mcp/` 与内置插件，并说明安装、更新或移除会做什么 |
| `editor.addon.install` | 写入插件及其归属清单，拒绝任何已被占用的路径；设置 `enable` 时还会启用插件 |
| `editor.addon.update` | 替换你没有改过的文件，补上缺失的文件；你改过的文件会作为备份保留在新文件旁边 |
| `editor.addon.remove` | 删除仍与安装时一致的文件并停用插件；你改过的文件会保留 |

编辑器在启用了插件的情况下启动时会加载它，或者在 **项目设置 → 插件** 里启用它时加载。更新之后，用 `editor.addon.reload` 加载新文件。

## 编辑器怎样连接

当项目在带有编辑器工具的 profile 下被绑定时，服务器监听一个临时的回环端口，并在项目的 `.godot-mcp/` 目录里写一个会合文件：端点、一个全新的 256 位密钥和项目的标识，只有你的用户能读。插件读取这个文件，连接端点，并证明自己读过这个文件；不带密钥的回环连接会被拒绝。一次只服务一个编辑器；服务器重启后，插件会自己找到它和它的新密钥。

`editor.status.get` 报告是否有编辑器连接、它的 Godot 和插件版本、内置插件是否是另一个版本、打开的场景和脚本、正在编辑的场景、选择、撤销历史、当前显示的主界面，以及是否有游戏在运行。没有编辑器连接时，其他编辑器工具都答复 `unavailable` 并指明缺的是编辑器。已连接的插件版本太旧、不支持某个工具时，这个工具答复 `unsupported`，并提示先更新插件。

## 它能做什么

| 工具 | 作用 |
| --- | --- |
| `editor.scene.tree.get` | 编辑器持有的当前场景，包括未保存的改动，附带语义摘要 |
| `editor.node.get` | 一个节点的全部信息：每个属性的类型、值和默认值，以及它的信号和连接 |
| `editor.types.get`、`editor.types.search` | 这个确切 Godot 版本看到的某个引擎类或项目类，或名字匹配的那些类 |
| `editor.scene.edit` | 把编辑器持有的场景改动作为一次可撤销操作，不保存 |
| `editor.scene.save` | 保存当前场景、某个打开的场景或全部打开的场景 |
| `editor.scene.open`、`editor.scene.close` | 打开一个场景；关闭一个没有未保存改动的场景 |
| `editor.selection.set` | 替换当前选择 |
| `editor.undo`、`editor.redo` | 通过编辑器自己的撤销和重做，在当前场景的历史里撤销或重做 |
| `editor.main_screen.set` | 切换到 2D、3D 或 Script 界面 |
| `editor.screenshot.capture` | 截取编辑器窗口，或它的 2D 视口、某个 3D 视口 |
| `editor.log.get` | 编辑器记录的日志：打印、错误和警告，附带出处 |
| `editor.filesystem.scan` | 接收磁盘上变化的文件、导入它们，并重新载入有变化的已打开脚本 |
| `editor.script.open` | 在指定的行和列打开一个脚本 |
| `editor.preferences.get`、`editor.preferences.set` | 读取和修改编辑器自己的设置，即编辑器设置对话框里列出的那些 |
| `editor.shortcuts.get`、`editor.shortcuts.set` | 读取和重新绑定编辑器的快捷键，即快捷键页里列出的那些 |
| `editor.play.start`、`editor.play.stop` | 像编辑器的运行按钮那样运行游戏，以及停止它 |
| `editor.addon.reload` | 重新加载插件，编辑器随后重新连接 |

读取从不改变编辑器状态：不打开任何东西，不选择任何东西，不把任何东西标为未保存，也不往撤销历史里添加任何东西。

## 修改编辑器持有的场景

`editor.scene.edit` 接受与 `scene.batch.apply` 相同的类型化操作，节点用路径指定，作用于编辑器持有的场景，包括未保存的改动。请求要带上 `editor.scene.tree.get` 或 `editor.node.get` 返回的摘要：场景在那之后变过，这次修改就会被拒绝，什么都不改。整次修改是编辑器撤销历史里的一个操作，名字取自你给的 `label`；在调用 `editor.scene.save` 之前什么都不保存。只有编辑器报告场景已保存，或者文件里的场景与编辑器持有的一致，保存才算数；否则答复 `uncertain`。保存场景时，编辑器里有未保存修改的脚本也会一起保存，所以你没保存的脚本不会挡住修复。

对编辑器里打开着的场景调用 `scene.batch.apply`，同样在编辑器里执行：编辑器里的副本必须与文件一致，成功后整批改动是一次撤销操作，场景随之保存。对编辑器占着的文件做无窗口写入会以 `conflict` 被拒绝，所以编辑器和服务器永远不会互相覆盖。

## 图块、动画、曲线和主题

画图块、给动画打关键帧、给曲线加点，都没有可以直接设置的属性，所以批处理用 `call_method` 操作来完成这类修改。它只能调用一张固定表里的方法：`TileMapLayer` 和 `GridMap` 的格子、`Line2D` 的点、曲线和渐变、`AnimationPlayer` 的动画库、动画、轨道和关键帧、`SpriteFrames` 的帧，以及 `Theme` 的条目。调用的对象是场景里的节点，或者场景内嵌的资源；单独保存成文件的资源用 `resource.batch.apply` 修改。参数会按你所用 Godot 版本里该方法的签名检查；像添加动画这类调用可以传入一个新资源；每次答复都列出每个调用的返回值。在编辑器里，这些调用和其他修改一样可以撤销。完整的表和规则见[编辑器桥参考](../../../operator/editor-bridge.md#editing-calls)。

## 项目文件归编辑器所有

编辑器连接期间，`project.godot` 和导入缓存归它所有。`project.settings.patch` 改由编辑器执行，编辑器按自己的格式写这个文件，不保留注释。导入也经由编辑器：`project.import.run` 和 `project.uid.update` 会被拒绝，改用带 `reimport` 的 `editor.filesystem.scan` 导入你指定的资源。

## 查看编辑器和读取日志

`editor.screenshot.capture` 需要带窗口的编辑器，截图以 artifact 返回。`editor.log.get` 从一个游标开始读编辑器日志，所以客户端每条日志只读一次；它需要 Godot 4.5.1 或更新版本。

## 编辑器自己的设置

`editor.preferences.get` 按名字或逐页读取编辑器的设置，每项给出类型、值、默认值和提示，以及修改后是否需要重启编辑器。`editor.preferences.set` 修改这些设置，要么全改，要么一项不改：值的类型不对，或超出设置的范围或可选项，就什么都不改。编辑器像它的编辑器设置对话框那样应用改动，并把它保存到你的编辑器设置文件里。这个文件属于你，不属于项目：编辑器打开的每个项目都用它，所以答复会给出每一项改动前后的值，方便改回去。会启动程序、保存路径、主机或凭据、或者让编辑器自己重新扫描的设置，永远不会从这里修改，其中保存路径或凭据的设置也不会读出来；[编辑器桥参考](../../../operator/editor-bridge.md#the-editors-settings) 列出了它们。

编辑器可能会随之改动别的设置，答复会把这些也列在 `also_changed` 里。主题预设控制的颜色，只有在预设为 `Custom` 时才能保留新值：Godot 4.7.1 会自己把预设切换过去，而 4.4.1、4.5.1 和 4.6.1 会把颜色改回预设的值，所以这次修改会被拒绝，什么都不改。请像编辑器设置对话框那样，在同一次修改里把预设设为 `Custom`。

## 编辑器的快捷键

`editor.shortcuts.get` 列出每个编辑器快捷键（比如 `script_editor/save`），以及快捷键页“Common”一组里的每个内置动作（比如 `ui_accept`），每项给出触发它的按键和默认按键；加上 `changedOnly` 只列出你改过的那些。`editor.shortcuts.set` 重新绑定它们，要么全改，要么一项不改：每个名字对应它的按键列表，空列表表示不绑定，`default` 表示恢复默认。按键用 Godot 的键名（`S`、`F9`、`Enter`）表示，修饰键用标志表示，其中 `command_or_control` 在 macOS 上是 Command，在其他系统上是 Ctrl。编辑器像它的快捷键页那样应用改动，并保存到你的编辑器设置文件里，答复给出每一项改动前后的绑定。Godot 4.4.1 和 4.5.1 不把快捷键交给插件，所以在这两个版本上两个工具都答复 `unsupported`。

## 关闭场景

`editor.scene.close` 关闭正在编辑的场景或另一个打开的场景。Godot 关闭场景时会直接丢弃其中未保存的改动，不会询问，所以场景里还有文件中没有的改动时，关闭会被拒绝：先保存，或者撤销这些改动。关闭需要 Godot 4.5.1 或更新版本。

## 磁盘上变化的文件

脚本或资源在磁盘上被改过之后，用 `editor.filesystem.scan` 让编辑器察觉：它重新扫描，导入变化的内容，并重新载入每个文件有变化的已打开脚本，除非这个脚本里有未保存的修改。没有重新载入的脚本会连同原因一起列出。会启动外部导入程序（比如 Blender）的扫描会被拒绝。

## 运行游戏

`editor.play.start` 运行主场景、正在编辑的场景或你指定的场景，`editor.play.stop` 停止它。编辑器会先保存打开的场景，答复里列出它保存了什么。这需要带窗口的编辑器；编辑器需要先问你什么的时候，比如哪个场景是主场景，启动会被拒绝。游戏作为编辑器自己的进程运行，在服务器的进程边界之外，所以配置为不受信任的项目会被拒绝；请改用托管会话运行它的游戏（见[会话](sessions.md)）。

## 答复丢失时

每次编辑器改动的结果只有三种：`committed`、`not_started` 或 `unresolved`。`unresolved` 指请求已经到达编辑器，却没有收到答复，或者它做的保存无法证明；这时答复是 `uncertain`，这次改动永远不会再发送一次，无论是重试还是编辑器重新连接之后。可能已经保存过文件的这类改动会阻止后续写入，直到它被解决（见[恢复](../operate/recovery.md)）。

## 它不做什么

上面列出的那些编辑器设置、Godot 4.4.1 和 4.5.1 上的快捷键、重启编辑器、素材库和版本控制，交给你自己或你已经在用的工具；断点和读取运行中的游戏在托管会话里（见[会话](sessions.md)）；内嵌资源的单个属性，通过把整个资源改好后写回来修改；丢弃未保存的改动和运行任意代码不提供。每一项的做法见[编辑器桥参考](../../../operator/editor-bridge.md#what-the-add-on-does-not-do)。
